# gsd-plan

Method text: the orchestration of upstream `plan-phase` is the workflow script below; its step 8 and step 12 contracts are generated unchanged in `.agents/gsd/generated/plan-phase-contracts.md` and reach the planner through its role include, then apply `.agents/workflows/gsd-overlay.md` and the overlay below (overlays win). The researcher, planner and checker are always separate agents; planning never creates, renames or switches git branches.

## Kit overlay

### Phase (GSDF-35, GSDF-33)
- Without a phase argument pick the first phase (lowest first, `ph gsd roadmap analyze`) whose status is `NOT_STARTED` or that is discussed or researched but unplanned; when none fits, ask.
- The run refuses a `COMPLETE` phase (`refused`, pointing at its VERIFICATION) unless the owner says force: pass `"force": true` and show the warning banner.
- The run refuses a `phaseDir` whose number matches a phase but whose directory is not that phase's directory (`refused`, naming both paths): pass the directory `find-phase` reports; it never plans into a stale slug.
- The run holds the phase lease `phase-<NN>` for its whole run, not the code-root writer lease, so planning phase N+1 can run while phase N executes. It is `refused` while another plan of this phase or an execute of this phase holds the lease; the reason names the holder's workflow and run.

### Run (GSDF-15, GSDF-02)
Args file `_workspace/args/gsd-plan.json`, e.g. `{"phaseDir": ".planning/phases/02-api"}`; optional `mode` (`plan` | `gaps`), `tracer` (default true), `reversibilityGates` (default true), `maxSkeletonPasses` / `maxCheckIterations` (integers 1..3, defaults from `gsd`), `skeletonLanes` (`[{lens, model?, effort?}]`, lens `fidelity`, `integration` or a `review_lenses` entry of stage `skeleton`; default `gsd.skeleton_lanes`; a changed lane set, lens text or reviewer definition reruns the skeleton review), `wiring` (`auto|always|never`), `replan`, `skipResearch` + `researchSkipReason`, `forceProceed {reason}`, `planReview`, `reviewGuidance` (the owner's answer to a Plan review stop: passed to the review's finder, verifier, judge and editor), `roles {role: {model, effort}}`. The roles this workflow passes, their agent types and tiers are in the kit's `docs/INTERFACES.md` section 4.2 (Role catalog).
`node .agents/harness/ph.mjs workflow --name gsd-plan --args-file _workspace/args/gsd-plan.json --detach`, then wait as `next:` says. Rerunning with the same args reuses what did not change: the outline unless its files changed or `replan` is set; the skeleton review unless its lanes, skeleton role, tracer or limit changed; the plans unless their files or the planning settings or planner role changed; the checker unless its plans or checker settings changed. A run that died is continued with `ph workflow --resume <runId>`.

### Results
- `planned`: apply the architect's `sharedChanges` the result lists (those without `executionWave`) before the first wave; the plans' own shared changes carry `executionWave` and gsd-execute makes them before that wave's gate. STATE already says `Ready to execute` and the ROADMAP carries wave headers. Show the `advisories` too: plan-review findings that did not block convergence (medium or low, not actionable) are listed there with their plan. Then chain: `gsd-execute`, then `gsd-verify`, stopping at the first `needs-owner` or `failed`. `--plan-only`: stop after the handoff.
- `needs-owner`: show `stage`, `reason`, the issues or the conflict, and the `options` numbered. For an owner marker also show `summary`, `question` and every item of `plans` (the planner's proposed split or audit options) so the owner decides without opening the run journal. Typical stages: Discuss (finish gsd-discuss), Research (run gsd-research, or rerun with `skipResearch` and a reason the owner gives), Skeleton review / Checker (open blockers or a stall: guidance and rerun, or `forceProceed {reason}` at the checker cap, never over an open REVISION_CONFLICT; the cap and the stall test count per plan, so the other plans finish their revisions first and the stop lists only the plans that got stuck, named in `reason`), Plan review (show the conflict and the issues; give `reviewGuidance` or record the decision in CONTEXT, then rerun; `planReview: false` disables the review), Dependencies (the adapter's `dependency_probe` exited non-zero or could not run: show `output` and `dependencies`; fix the `<path>: dependency` lines of the plans or the probe, then rerun, or rerun with `replan` so the planners rewrite the plans), Plan (owner marker such as PHASE SPLIT RECOMMENDED), Handoff (coverage gate: re-plan, move to a later phase, or tag the decision informational in CONTEXT).
- `failed` / `refused`: report the reason; nothing to chain.

### Standalone plan review (GSDF-37)
To review plans that already exist without the rest of gsd-plan, write an args file such as `{"phaseDir": ".planning/phases/02-api", "plans": ["02-01", "02-02"]}` and run `node .agents/harness/ph.mjs workflow --name gsd-plan-review --args-file _workspace/args/gsd-plan-review.json --detach`.
- `phaseDir` (required) matches `.planning/phases/NN-name`. `plans` (required) lists plan ids in the `NN-MM` form; an id outside that form is dropped without a message, and when none is left the run fails.
- Optional `roles {role: {model, effort}}` for `plan_finder`, `plan_verifier`, `plan_judge` and `plan_editor`, and `researchPath`, the one research report the reviewers may read. Without `researchPath` no RESEARCH.md is read.
- Each cycle runs one finder per plan and lens, except a plan that kept no issue in the last cycle, until its file changes. The `plan_review` lenses from `adapter.review_lenses` run first, then the built-in `source-grounding` lens, which always runs when plan review runs (there is no switch).
- The cycles follow the trend: only `high` issues block convergence and reach the editor, and the review goes on while their count falls, stopping `needs-owner` when it does not. The editor rewrites the listed PLAN.md files in place and the handoff is regenerated. The medium and low issues of a converged review are notes: written to `<phase>/plan-review-notes.json` and handed to each plan's executor by gsd-execute. Only the review runs: no outline, skeleton review, checker or coverage step, so a `converged` result does not replace them.
- Results: `converged` (`cycles`, `planRevision`, and the kept medium and low `issues`), `needs-owner` (`reason` with `issues` or `conflict`) or `failed` (`reason`).

### Gap closure (GSDF-30, GSDF-56)
After `gsd-verify` returns `gaps_found`, run with `{"phaseDir": ..., "mode": "gaps"}`: one gap wave only, `handoff/gap-w1.args.json`, then `gsd-execute --gaps-only` and `gsd-verify` again. A second gap attempt after a gap wave ran returns `needs-owner`: leftovers go to the owner (a new phase).

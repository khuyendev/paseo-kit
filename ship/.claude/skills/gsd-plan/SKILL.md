## Kit contract

Method text: the orchestration of upstream `plan-phase` is the workflow script below; its step 8 and step 12 contracts are generated unchanged in `.agents/gsd/generated/plan-phase-contracts.md` and reach the planner through its role include, then apply `.agents/workflows/gsd-overlay.md` and the project section below (overlays win). The researcher, planner and checker are always separate agents; planning never creates, renames or switches git branches.

The workflow is the project's composition `.agents/workflows/gsd-plan.js` and `.agents/workflows/gsd-plan-review.js`: a script of kit verbs that the project owns and evolves. This block is the kit's contract for every composition; the project section below the markers describes what this project's script takes and returns.

Run: write the args file `_workspace/args/gsd-plan.json` (its fields are in the project section), run `node .agents/harness/ph.mjs workflow --name gsd-plan --args-file _workspace/args/gsd-plan.json --detach` and wait as its `next:` line says. A run that died is continued with `node .agents/harness/ph.mjs workflow --resume <runId>` (finished agent calls replay from the journal); a stopped run is answered, then run again with the same args.

Result statuses (the success statuses, stages and fields of this script are in the project section):
- `needs-owner`: show `stage`, `reason` and the numbered `options`, with the items the result lists for that stage. The answer is the verb the result names (an option, or the answer line of the stop, such as a `ph gsd ... clear` verb): run it as written, then run again with the same args. A stop that names no verb is answered by fixing the tree or the inputs it names, then running again. Quota or rate limits never offer retry-now: report the reset time.
- `refused`: another run holds the lease or lock the reason names; nothing was dispatched. Wait for it to end, then run again.
- `failed`: report the reason and the problems the result lists.
- Never edit the flow's state or record files by hand (progress, transfer, halt, request, answer and revision records, run journals under `_workspace/_runs/`): only the run and the `ph gsd` / `gsd-flow.mjs` verbs write them. Never edit the workflow script to get past a stop: composition changes go through harness-evolve between runs.

## Project composition

This section is the project's (outside the kit markers; kit updates never change it). It describes `.agents/workflows/gsd-plan.js` and `.agents/workflows/gsd-plan-review.js` as this project runs it: args, switches, stages and result fields. harness-evolve changes it together with the script; seeded from the kit default.

### Phase (GSDF-35, GSDF-33)
- Without a phase argument pick the first phase (lowest first, `ph gsd roadmap analyze`) whose status is `NOT_STARTED` or that is discussed or researched but unplanned; when none fits, ask.
- The run refuses a `COMPLETE` phase (`refused`, pointing at its VERIFICATION) unless the owner says force: pass `"force": true` and show the warning banner.
- The run refuses a `phaseDir` whose number matches a phase but whose directory is not that phase's directory (`refused`, naming both paths): pass the directory `find-phase` reports; it never plans into a stale slug.
- The run holds the phase lease `phase-<NN>` for its whole run, not the code-root writer lease, so planning phase N+1 can run while phase N executes. It is `refused` while another plan of this phase or an execute of this phase holds the lease; the reason names the holder's workflow and run.

### Pause on a stop request (kit feedback 88)
- `node .agents/harness/ph.mjs workflow stop <runId>` asks a running plan run to stop at its next boundary; it kills nothing. The run checks between planner waves (staged: after the wave's plans are recorded and its contract gate ran; streams: after the wave's join, contract gate and interface propagation) and before each checker round after the first of the checker loop (the round's revisions are recorded). The streams checker join and the review streams run on to their end.
- Result `paused` (stage `Plans` with `pausedAt {by: stop-request, afterWave, nextWave}`, or `Checker` with `pausedAt {by: stop-request, round}`) and `answer` verb `rerun`: run again with the same args; the recorded plans are kept and the checker judges them again.

### Owns grammar (kit feedback 74)
- `owns` is a path, a directory or a glob (`Path:lib/i18n/strings*.g.dart`); the plan checker, outline check, waves and the execute transfer read it with one matcher, so what the checks accept the transfer accepts. Output of a generator whose file set depends on its configuration: own the output directory, or a glob, or list the files the configuration fixes. `files_modified` holds files only: a `*` or `?` there is a blocker (`glob-files-modified`), and an owns glob with an unpaired `[` or `{` is `invalid-owns-glob`.

### Run (GSDF-15, GSDF-02)
Args file `_workspace/args/gsd-plan.json`, e.g. `{"phaseDir": ".planning/phases/02-api"}`; optional `mode` (`plan` | `gaps`), `tracer` (default true), `reversibilityGates` (default true), `maxSkeletonPasses` / `maxCheckIterations` (integers 1..3, defaults from `gsd`), `skeletonLanes` (`[{lens, model?, effort?}]`, lens `fidelity`, `integration` or a `review_lenses` entry of stage `skeleton`; default `gsd.skeleton_lanes`; a changed lane set, lens text or reviewer definition reruns the skeleton review), `wiring` (`auto|always|never`), `replan`, `replanPlans {plans, inputs}` (set only as a stop's `answer.args` names it, see below), `skipResearch` + `researchSkipReason`, `forceProceed {reason, issues?: [{plan, dimension}]}` (see Checker outcomes), `planReview`, `reviewGuidance` (the owner's answer to a Plan review stop: passed to the review's finder, verifier, judge and editor), `planFlow` (`staged` | `streams`, default `gsd.plan_flow`, shipped `staged`; see Streams flow below), `roles {role: {model, effort}}`. The roles this workflow passes, their agent types and tiers are in the kit's `docs/INTERFACES.md` section 4.2 (Role catalog).
`node .agents/harness/ph.mjs workflow --name gsd-plan --args-file _workspace/args/gsd-plan.json --detach`, then wait as `next:` says. Rerunning with the same args reuses what did not change: the outline unless its files changed or `replan` is set; the skeleton review unless its lanes, skeleton role, tracer or limit changed; the plans unless their files or the planning settings or planner role changed; the checker unless its plans or checker settings changed. A run that died is continued with `ph workflow --resume <runId>`: it keeps the outline and the plans that run already wrote and recorded (an edit its plan review made before it died included) and replays the finished calls. `<phaseDir>/plan-progress.json` is the run's planning record (written only by the flow's plan-* verbs; never edit it).

STATE already says `Ready to execute` and the ROADMAP carries wave headers. Show the `advisories` too: plan-review findings that did not block convergence (medium or low, not actionable) are listed there with their plan. For an owner marker also show `summary`, `question` and every item of `plans` (the planner's proposed split or audit options) so the owner decides without opening the run journal. Typical stages: Discuss (finish gsd-discuss; or, before an outline is written, `questions`: research Open Questions that ask for a scope or requirement decision, each answered with `ph gsd decide <N> --question <n> --text ...`; `ph gsd research questions <N>` lists them), Research (run gsd-research, or rerun with `skipResearch` and a reason the owner gives; research `provisional` was written ahead of an earlier phase still running: plan after that phase completes and gsd-research `refresh: "code"` ran; `code-stale`: run gsd-research `refresh: "code"`), Skeleton review / Checker (open blockers or a stall: guidance and rerun, or `forceProceed {reason}` at the checker cap, never over an open REVISION_CONFLICT, and not in the run that wrote the stuck plans (the stop says `forceProceed refused`; rerun with it); the cap and the stall test count per plan, so the other plans finish their revisions first and the stop lists only the plans that got stuck, named in `reason`; a REVISION_CONFLICT on one plan still lets the phase-level issues get their revision first, and the stop follows it; a checker blocker counts as open until a later checker lists its id in `resolved`, so a checker that says nothing about it does not clear it), Plan review (show the conflict and the issues; give `reviewGuidance` or record the decision with `ph gsd decide`, then rerun; `planReview: false` disables the review; in the streams flow `plan` names the one plan whose stream stopped, the plans of its wave that froze are recorded and no later wave was planned), Dependents (streams flow: a plan whose `depends_on` provider changed its declared interface still uses the old one after its revisions; show `plan` and `issues`; give guidance and rerun or fix the plan by hand), Smoke build (an `adapter.commands.smoke_builds` target did not build or could not run: show `builds`, each failing argv with its `output`; fix the `<path>: dependency` lines of the plans or the probe, then rerun, or rerun with `replan` so the planners rewrite the plans), Plan (owner marker such as PHASE SPLIT RECOMMENDED), Handoff (coverage gate: re-plan, move to a later phase, or tag the decision informational in CONTEXT).
- `failed` / `refused`: report the reason; nothing to chain.
- Codebase map (kit feedback 121): drift at `gsd.drift_threshold` is an `advisories` entry (`lane: "map"`) and `mapDrift`, and the run's final line names it. At `gsd.map_drift_block` (absent = 10 × the threshold; `0` = warn only) the run stops `needs-owner` at Preconditions before any agent. ### Checker outcomes (kit feedback 69, 71, 76)
- `forceProceed {reason, issues: [{plan, dimension}]}` accepts only the checker issues it names (`plan` a plan id, or null for a phase-level issue; `dimension` the checker's dimension, or the probe's name: `owns`, `files-per-plan`, `verify-command-paths`, ...). An accepted issue is taken out of the blockers of every round: the cap and stall tests do not count it and no reviser is asked for it (so it cannot end in REVISION_CONFLICT); every other issue is revised as before. If an issue is still stuck at the end, the run stops `needs-owner` with `issues` (unaccepted) and `accepted`. The accepted issues that occurred are written to STATE one by one, recorded in `<phase>/accepted-issues.json` (kit feedback 89: gsd-execute stops before the plans an open record affects until the owner replans, or answers `ph gsd accepted confirm|resolve <N> --id <AI-n> --reason <text>`) and returned in `override.accepted` (`override.unused` lists entries that matched nothing). The reason says why the issues are accepted now; a reason that promises a follow-up (will, later, follow-up, todo, before execute, ...) is refused, because the records are the follow-up. `forceProceed {reason}` alone keeps its old meaning, every issue still stuck at the end of the checker, and now writes them per issue (`override.mode` `all` vs `issues`) with a warning. Still refused for a plan this run wrote.
- `gsd.files_per_plan {warning, blocker}` sets the Files/plan lines; `ph gsd outline check` applies them to the owns of the manifest (an owns directory counts 1), so a plan that is too large is reallocated by the outline writer before skeleton review. An outline reused from an earlier run is only warned.
- Inherited tests (kit feedback 101): `ph gsd outline check` lists the existing test files the manifest's verify commands run (`inheritedTests`, with the plans that own each); one that no plan of the phase owns is an error: the outline assigns it (owns) to the plan that changes the behaviour it asserts, or drops it from the command. The skeleton lanes judge the list. An outline reused from an earlier run is only warned.
- Owner decisions (kit feedback 99): `ph gsd decide` writes the decision to `<phase>/owner-answers.json` (kind `decision`); the planners, the architect, the checker, the skeleton lanes and plan review read it. It is no research input: research stays approved, a decision with `--plans` re-plans only those plans (the outline, the skeleton review and the other plans stay), one with `--outline` (or `--question`) the outline and its plans. The same `--id` again replaces a decision; an id of CONTEXT.md is refused.
- `gsd.checker_reallocate` 1 or 2 (default 0; staged flow): a plan whose `files_modified` reaches the blocker line, or a checker issue with `outcome: "reallocate"`, ends the checker round before any revision and sends the named plans back to the outline stage: the outline writer changes only their owns, the skeleton lanes review the new allocation, the plans whose allocation changed (and new ones) are written again, the others keep their records, and the checker runs again over all plans. The result lists `reallocated: [{round, plans, changed, removed, issues}]`. When the rounds are used up the issue is a normal blocker. A stop `outline reallocation left <plan> unchanged` means the outline writer did not split it: give guidance, or accept the size with `forceProceed` `{plan, dimension: "files-per-plan"}`.
- `gsd.checker_recheck: "incremental"` (default `full`): after a plan edit the checker agent judges only the changed plans and the plans linked to them (`depends_on`, manifest `consumes`, `must_haves.key_links` endpoints inside another plan's write set); all deterministic probes run on every plan; an edit of only `owns`/`files_modified` starts no agent. Any other change (outline, manifest, wiring, settings, roadmap, a removed plan), `replan` or a missing record is a full check. The result lists `recheck: {mode, changed, bodyChanged, linked, agent}`.

- With `gsd.contract_check` (default on) the cross-plan contracts have one owner, the outline manifest: `produces` is `[{symbol, kind, file, signature}]`, and the planners write each produced signature verbatim and quote each consumed one in `<interfaces>`. `ph gsd verify contracts <phase>` runs after each planner wave (streams: at each wave's join), after the checker and plan review and at handoff with `--complete`; each issue goes to the plan whose planner can fix it (the verb's `fixers`: a missing or wrong consumed quotation to the consumer only, a superseded signature to the plan that still holds it, an unprovided precondition to the provider it names, an unresolved edge or a later-wave precondition to both; kit feedback 100), one `contract-<plan>-<round>` revision each, with the plan's manifest entry and the consumers of each produced symbol, outside the checker's cap; issues that do not fall stop `needs-owner` at stage `Contracts`. A reviser's REVISION_CONFLICT is judged only after the check ran again: one whose plan the check no longer routes an issue to is dropped (logged) and the gate goes on, so a passing re-check needs no owner answer; one whose issue is still there stops at Contracts. A reviser that must change a produced signature returns `contract_changes: [{plan, symbol, old, new, reason}]` (marker CONTRACT_CHANGE); the flow writes the manifest (`ph gsd contracts change`) and revises the consumers, and a change the manifest refuses stops `needs-owner`. After each outline revision in the skeleton review, a symbol the outline prose gives a new shape (a code span with a name its manifest signature lacks; a span qualified by another type is not this symbol's shape, and a span that is exactly another produced symbol belongs to that symbol) while its manifest signature stayed the same is contract drift (kit feedback 98, 114; the error names the other symbol when the span matches one): the outline writer gets one repair turn with it as errors, and drift left after it stops `needs-owner` at Skeleton review (`drift`, answer `fix-and-rerun`: make the manifest signature the outline's shape, or the span the signature) before any planner. A planner conflict that carries its own `contract_changes` answers `contracts-change` (`answer.changes`): apply each with `ph gsd contracts change <phase>` (stdin JSON `{plan, symbol, old, new, reason}`; `old` is `""` and `file` and `kind` are set when the symbol is not produced yet, and the file is inside the plan's owns — that plan and its consumers are planned again, not the outline). A new plan, wave or requirement stays `ph gsd decide --outline`. The CONTEXT decision stays an option. An ownership-only SOURCE AUDIT (`owns_changes`) of a wave is one stop, `owns-add`: `ph gsd owns add <phase> --plan <id> --path <p> --reason <text>` for a path no plan owns, or `ph gsd owns handover <phase> --from <id> --to <id> --path <p> --reason <text>` to move a path to a plan in another wave. Either drops only those plans' revision keys. A same-wave move, or a new plan, wave, requirement or producer order, stays `ph gsd decide --outline` (kit feedback W15, W16). A planner that needs a change in another plan returns `plan_changes: [{plan, change}]`: that plan is marked for re-planning in plan-progress.json and planned again with the note (its wave's planner in this run when it has not run yet; otherwise a re-plan pass before the checker, at most `maxSkeletonPasses` times). The checker does not start while a mark is still open: only a mark left after that bound stops the run at stage Plans with `replan` and answer `rerun` (a mark raised during the checker still stops at the handoff the same way; kit feedback 99 F3, 115 F1/F2). Each plan id NN-MM is the threat-id range T-NN-MMxx (that prefix plus exactly two digits); the planner prompts quote it, and a plan that uses an id outside its range is a checker probe blocker of dimension `threat-id` (kit feedback 115 F3). A precondition (an ancestor widget, a provider override, a registration) is a `must_haves.key_links` entry `requires: {kind, name, by}` that a plan of the same or an earlier wave lists as `provides: {kind, name, at}`. The result's `contracts` says how many checks, rounds and changes ran. gsd-execute's wave gate checks the produced symbols exist at their declared file (step `contract-<plan>`). A `.json` file, or a file matching `adapter.catalogs`, whose signature is a key path (`a.b { c, d }` means keys `a.b.c` and `a.b.d`; `name({{token}})` is the key `name`) is checked by those keys; a missing key is a note naming the path, and any other file is a note only when it holds no equivalent declaration (a body, a parameter name, a `this.name` or `super.name` field formal, a multi-name field; a name, kind, type, arity or optionality mismatch still notes, and `<` `>` stay as written; kit feedback 103, 116).

### Streams flow (kit feedback 65, 67)
With `gsd.plan_flow: "streams"` (or arg `planFlow: "streams"`; gap mode ignores it) each plan gets its own review stream as soon as its planner returns: the finders of that plan, its verifier and judge, an editor of that plan only, then a resolution check of only its open high issues (no fresh find), again while the open count falls; a plan with no open high issue is frozen. The streams of one wave run at once (the engine queues past `max_subagents`) and none waits for another; the next wave's planners start once every plan of the wave froze, so later plans are written on reviewed plans. The checker then reads the frozen set once and sends each blocker back to only the plan it names (revision, structure check, record, then that plan's probes and a resolution check of its blockers, at most `maxCheckIterations` judgments per plan); phase-level blockers get the phase-level revision afterwards, and a final probe pass closes the join. Whenever a revision changes a frozen plan's declared interface (`must_haves.artifacts`, `must_haves.key_links`, `<interfaces>` blocks), every plan whose `depends_on` names it gets a dependency check and, on a blocker, a revision of its own, before execute. `forceProceed` works at the checker join as in the loop. Rerunning keeps recorded plans; their streams run again (a `--resume` of a dead run replays the finished calls).

### Standalone plan review (GSDF-37)
To review plans that already exist without the rest of gsd-plan, write an args file such as `{"phaseDir": ".planning/phases/02-api", "plans": ["02-01", "02-02"]}` and run `node .agents/harness/ph.mjs workflow --name gsd-plan-review --args-file _workspace/args/gsd-plan-review.json --detach`.
- `phaseDir` (required) matches `.planning/phases/NN-name`. `plans` (required) lists plan ids in the `NN-MM` form; an id outside that form is dropped without a message, and when none is left the run fails.
- Optional `roles {role: {model, effort}}` for `plan_finder`, `plan_verifier`, `plan_judge` and `plan_editor`, and `researchPath`, the one research report the reviewers may read. Without `researchPath` no RESEARCH.md is read.
- Each cycle runs one finder per plan and lens, except a plan that kept no issue in the last cycle, until its file changes. The `plan_review` lenses from `adapter.review_lenses` run first, then the built-in `source-grounding` lens, which always runs when plan review runs (there is no switch).
- With `gsd.plan_review_check` `resolve` (default, kit feedback 72) only the first pass is a fresh review. After each edit a resolution check of the open issues (one read-only call per plan that has some) runs together with a finder limited to the lines the edit changed (it may name another plan that relies on them); the cycle's `counts` entry then also has `fixed`, `stillOpen` and `new`. The review stops `needs-owner` as not converging only when the edit fixed none of the issues it was sent; new high issues join the next edit, and the edits may introduce them in at most 2 rounds before the review stops. The medium and low notes of every pass are kept. `fresh` is the cycle below, which stops when a fresh review's high count does not fall (even if every earlier issue was fixed). The streams flow always resolves.
- The cycles follow the trend: only `high` issues block convergence and reach the editor, and the review goes on while their count falls, stopping `needs-owner` when it does not. The editor rewrites the listed PLAN.md files in place and the handoff is regenerated. The medium and low issues of a converged review are notes: written to `<phase>/plan-review-notes.json` and handed to each plan's executor by gsd-execute. Only the review runs: no outline, skeleton review, checker or coverage step, so a `converged` result does not replace them.
- Results: `converged` (`cycles`, `planRevision`, the kept medium and low `issues`, and `counts`: one `{cycle, high, mediumOrLow}` per cycle, the last one from the pass that converged; `resolve` adds `fixed`, `stillOpen`, `new` to the cycles after the first), `needs-owner` (`reason` with `issues` or `conflict`, and the same `counts`) or `failed` (`reason`). gsd-plan's Plan review stop carries `counts` too.

### Gap closure (GSDF-30, GSDF-56)
After `gsd-verify` returns `gaps_found`, run with `{"phaseDir": ..., "mode": "gaps"}`: one gap wave only, `handoff/gap-w1.args.json`, then `gsd-execute --gaps-only` and `gsd-verify` again. A second gap attempt after a gap wave ran returns `needs-owner`: leftovers go to the owner (a new phase).

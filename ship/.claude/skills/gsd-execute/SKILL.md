# gsd-execute

Method text: the orchestration of upstream `execute-phase` is the workflow script below; for each plan follow `.agents/gsd/generated/workflows/execute-plan.md` (generated upstream text, unchanged; the executor's deviation rules, `.agents/gsd/generated/executor-rules.md`, reach it through its role include), then apply `.agents/workflows/gsd-overlay.md` and the overlay below (overlays win).

## Kit overlay

### Run (GSDF-93)
Args file `_workspace/args/gsd-execute.json`: `{"phaseDir": ...}` plus `wave` (N), `plans` (`"03-01,03-02"`), `gapsOnly` (true) or `files` (an explicit review file list for the per-plan reviews; the batch phase review always covers the whole phase diff). Run `node .agents/harness/ph.mjs workflow --name gsd-execute --args-file _workspace/args/gsd-execute.json --detach` and wait as `next:` says. Never start execution from inside a `ph` agent worktree or on a `harness/*` branch (the run refuses and lists stranded commits and dirty files).

### What the run does
- Refuses a phase without `handoff/` (plan it first), a `--wave` while lower waves are incomplete, and `--gaps-only` when a plan lacks the `gap_closure` key.
- Refuses a handoff that no longer matches the plans (a plan edited, added or deleted after the handoff, or a wave set cut short by a failed handoff): plan the phase again.
- Safe resume: an execute baseline is recorded once; before every dispatch changed files are matched to plans (a nested path belongs to the plan owning it most specifically; a tie between equally specific owners goes to the plan whose transfer record holds the path, the latest one when several do), and an incomplete plan with changes, an unowned changed path, a foreign HEAD move or commits without a SUMMARY stop the run (`needs-owner` with paths, owning plan and HEAD; options close out manually, re-execute from scratch, mark and skip). A commit between runs that touches no file any plan of the phase owns (a docs commit) is accepted and logged; a commit of the run whose `commits.json` record failed is reconciled from its `Plans:` trailer. Paths matching `adapter.ownership.ignore` (notes the owner keeps during a run) are never plan output. After an owner's hand fix to a file a plan transferred, record it with `node .agents/workflows/lib/gsd-flow.mjs adopt <phaseDir> <plan> <path>`: it re-hashes that path in the plan's transfer record and refuses a path that record does not hold or a transfer that did not finish. Never edit a transfer record by hand.
- Halts: a halted plan (Rule 4, checkpoint, failed executor) and its dependants are skipped and listed in the result's `skipped`; answer the halt with `node .agents/harness/ph.mjs gsd halt clear <N> --plan <id> --reason "<answer>"` and rerun: the plan is dispatched again with the answer in its prompt.
- Change requests: a request for a file another open plan owns reaches that plan's executor or fixer; a request for a file no open plan owns (none, or a plan already committed) and the plans' `<shared_changes>` of the wave are made by one integration fixer owning exactly those paths before the gate, and committed with the wave. A review fixer that needs a file a committed plan owns and cannot change it stops the run `needs-owner` with `grantRequests` (each path and its owning plan) and one option per path: `node .agents/harness/ph.mjs gsd grant <N> --path <file> --plan <id>` (no `--plan` when no plan owns the file), then rerun with the same args. The grant lets the phase's fixers change that file, and the file joins the wave commit as integration, recorded in `commits.json`.
- One `gsd-executor` (or the adapter's executor agent) per plan, at most `gsd.parallelization.max_concurrent` at a time (one at a time when parallelization is off); plans sharing a modified file run one after the other. With `gsd.isolation: worktree` each executor works in its own worktree and the orchestrator transfers the owned changes in plan order. A change outside a plan's owns refuses its transfer (the plan halts), except a path matching `adapter.ownership.regenerated` or a tracked file that differs from HEAD only in line endings: those are dropped, logged as `transfer <plan>: <path> not copied`, and listed in the transfer record. The executor brief tells executors to delete the scratch files they create outside owns before they return.
- Smoke build (F57): the first wave (`per-wave`) or the batch (`batch`) that changes a file matching `adapter.smoke_triggers` (dependency manifests, native-asset package files) builds `adapter.commands.smoke_builds` once per phase, before its gate. A failing or unrunnable target stops the run `needs-owner` at stage Smoke build with the failing argv and output; a passed build is kept in `execute-progress.json`, so a resumed run does not build again. Nothing runs while `smoke_builds` is empty.
- Gate after each wave (`per-wave`) or once at the end (`batch`): adapter gates, build, tests, every plan obligation; one evidence file per gate run under `<phaseDir>/evidence/`. In `per-wave` one more gate runs after the last wave is committed, over every plan of the run (`batch-<n>.json`, kit-feedback 58): a wave's gate goes stale once a later wave edits the same files, so that file is the phase's evidence. A red phase gate stops the run with the waves still tracked. Tracking (STATE wave log) moves only on green evidence.
- Review after green: one `gsd-code-reviewer` per plan, blocking findings verified by `finding-verifier` (a second, independent verifier decides what the first left uncertain), one `gsd-code-fixer` pass, a resolution check, and one more fixer pass limited to the findings still unresolved; one finding per defect class carries its instances. A rerun reuses the recorded review of unchanged code, and after a fix pass (a stop at Review, or a hand fix of the last instances) runs only the resolution check. Main-tree edits outside every plan's owns stop the run before the gate and the review. Non-blocking findings, and findings outside the lines the plan changed that the change did not cause (pre-existing), go to `<phaseDir>/deferred.md`; metrics to `_workspace/review-metrics.jsonl`. With `gsd.review_metrics` (default on) the verifier also tags each confirmed finding plan-catchable, and every executor halt, red gate and fix call (per wave, or per plan and commit batch under the graph schedule) is recorded with the plan defects named for it in `<phaseDir>/prereview/execute-<runId>.json` (measurement only; `ph review-stats --stage`).
- Commits by the orchestrator only (`feat(<phase>-w<k>)` per wave or `feat(<phase>-<plan>)` per plan with a `Plans:` trailer), recorded in `<phaseDir>/commits.json`.
- Schedule (`gsd.execute_schedule`, kit-feedback 66). `waves` (default) is everything above: each wave is coded, gated, reviewed and committed before the next starts. `graph` needs `execution_mode: per-wave`; with `batch` the run is refused. Under `graph`:
  - A plan starts as soon as the plans it waits for are committed. It waits for its `depends_on`, for any earlier plan whose owns or `files_modified` overlap its own, and for the tracers of earlier waves. A cycle is refused.
  - Each plan then runs alone: its executor and transfer, a gate of only its own obligations (`<waveId>-<plan>-<n>.json`) with fix rounds, then its review, fixer and resolution check. A red plan holds only itself and the plans that wait for it.
  - Ready plans join one commit queue. Each batch runs the repo-wide suite (adapter gates, build, tests; `join-<n>.json`) and is committed on green, one commit per handoff wave in the batch (or per plan with `per-plan`).
  - Suite failures in the batch's files go to fix rounds. Failures only in files of another open plan make the batch wait for that plan, and the two commit together. An obligation that failed only in another open plan's files runs again with that suite.
  - The phase gate at the end is the same as under `waves`.
  - Gates, stray and resume checks and commits never overlap a main-tree writer (shared-tree executor, transfer, fixer). With `isolation: shared`, a gate therefore waits for running executors; `worktree` keeps executors parallel to gates.
  - Reviews across plans are capped by `gsd.code_review.max_concurrent` (default 1). Raise it to review plans in parallel.
  - The result adds `schedule: "graph"`, `order` (start and commit order) and `committed`.
  - One plan's stop leaves the others running to their commit. Its dependants are listed in `skipped` ("blocked by"). The result is the first stop plus `stopped` (every stop).
  - A quota stop, or any failed or refused step, drains the run: plans not committed are listed in `interrupted`.
  - Rerun with the same args to resume. Committed plans are kept, coded plans go straight to their checks, and recorded reviews are reused.

### Results
- `executed`: run `gsd-verify` with `evidence` = the result's evidence list (in `per-wave` that is the one phase gate file). When the result has `skipped`, report those plans first (halted or blocked): the phase is not complete.
- `nothing-to-run`: follow `route` (verify, complete, plan-gaps, uat, stuck: answer the halt named with `ph gsd halt clear`, never "done").
- `needs-owner`: show stage, reason and options. Quota or rate limits never offer retry-now: report the reset time. A Rule-4 or checkpoint result needs the owner's decision; a red tracer wave starts no later wave. A Fix stop whose reason says `last edit unverified` means the fixer's last edit has no build or test run after it: run the failing tests before any hand fix.
- `refused` / `failed`: report the reason. `refused` names the holder: a plan or an execute of this phase (`phase-<NN>` lease), or a debug or quick run on the code root.

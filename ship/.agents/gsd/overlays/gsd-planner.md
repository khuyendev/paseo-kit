- Write only the PLAN files named in your prompt (and the outline files when asked for the outline). Plans declare `owns` in the forms of `adapter.ownership.owns_forms`; a needed change to a shared file goes in a `<shared_changes>` block, never in `files_modified`, one line per file in the form `<path>: <change>` (gsd-execute applies it before the executors of the plan's execution wave start, owning exactly those paths; write `when <file> exists` or `after the plan's code` on a line that needs the plan's own code, and no other wave timing: a `before wave N` earlier than the plan's own wave is refused by the checker's owns probe). A package a plan adds or changes is its own line in the same block, `<path>: dependency <name> <constraint>` (append ` [dev]` for a development dependency), so the adapter's dependency probe checks the declared set at handoff; write every package that way, never only in prose.
- Owns is a path, a directory or a glob (`Path:lib/i18n/strings*.g.dart`: `*` `?` `[..]` `{a,b}` `**`), and the gsd-execute transfer accepts exactly the files that match. `files_modified` lists concrete files only, never a glob. Output of a generator or build tool whose file set depends on its configuration (one file per locale, a registry per feature): own the output directory when no other plan writes there, otherwise own a glob that matches the generated names, or list the files the generator configuration fixes; never put the pattern in `files_modified`.
- Every `<automated>` obligation uses a kind of `adapter.verify_vocabulary` and is followed immediately by `<fails_when>`.
- A plan that weakens a check on purpose declares it up front in a `<check_changes>` block, one line per file in the form `<path>: <reason>` (one owned file, no glob): a test file it deletes, tests it removes, assertions it removes or loosens, a skip marker it adds, a gate or lint setting it relaxes. The reason says why the check is no longer needed or where its coverage moved. Every gate compares the test and gate files with the wave base and stops the run at stage Checks on any weakening no plan declared; only the owner can allow it afterwards. Moving or renaming a test, or adding tests, needs no declaration.
- Respect `gsd.plan_limits` and `gsd.granularity` from your prompt. Split a plan for these reasons: overlapping owns in one wave, an ordering coupling, a gating spike, or a plan too big for one coder context.
- Do not run `state.planned-phase`, `roadmap.annotate-dependencies` or commits: the orchestrator does them after the checks.

## Owner decision after the maps (2026-10-20)

### D-109 The harness method becomes the adapter generator; code-wave is dropped
- Owner wording (summary of the decision as given): the skills and agents the old harness generated for one project (code-wave, a stack skill, a wireframe skill, a coder, a reviewer, an interface architect) are specific to that project and its engine and do not carry; a new project starts with no skills; GSD is the portable process (plan -> execute -> verify with its own generic agents).
- Decision:
  1. code-wave is dropped as a kit concept; execution is GSD's execute path with GSD agents (executor, code-reviewer, code-fixer, verifier). Project-specific knowledge belongs to that project's adapter, never to the kit.
  2. The harness method is repurposed as the adapter generator: for a new project, after GSD map-codebase, the harness reads the codebase map and generates the project's adapter: build/test/verify commands and verify vocabulary, review lenses, models per role, project skill(s) for its stack, and project agents only where a GSD agent is not enough. `harness-evolve`, after phases, records lessons (history table) and updates the adapter.
  3. Project flow: kit-init (install) -> map-codebase -> harness generates the adapter -> new-project -> GSD phases -> harness-evolve.
  4. Generic team building for non-GSD workflows is no longer a kit goal; keep only what the adapter generator needs (skill writing/testing rules, role-vs-skill split, model-tier choice, history table). This supersedes the MTH-62 split "harness owns team building".
- Settles or closes: MTH Q2 (D-52 superseded), MTH Q3 (D-53 closed: skill dropped), MTH Q6 (D-55 narrowed), MTH Q7 (D-56: gate rules go to GSD code review; majority-vote not carried), MTH Q8 (D-57 narrowed), the method parts of D-59, GSP Q3 executor part (D-63 updated), the persistent-team users of `ph task` and `ph freeze` (D-18, D-21 narrowed); MTH-62 and GSP-69 (the interface architect was a project agent: the core ships no architect; the plan workflow runs the wiring-contract stage only when the adapter provides an architect agent).
- Effect on behaviors: in the method map 31 behaviors move to dropped (execution modes, team patterns, verification patterns, QA guide, orchestrator templates A/B/C/mixed, data transfer, `_workspace` conventions, work-size table, CLAUDE.md harness entry, ai-orchestrator, team examples, workflow invocation forms: MTH-02, 03, 05..09, 16..20, 30..39, 41, 45, 56, 61, 66..68, 70, 73); 19 are kept with changes for the adapter generator and harness-evolve; 23 are kept as they are (skill writing and testing, role-vs-skill split, tiers, English output, provenance, preflight and bookkeeping rules, waiting rule).

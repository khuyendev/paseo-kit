The contracts every module codes against. Written by code-foundation; other coders do not edit this file (file a request, see "Integration requests"). Requirement IDs refer to `.planning/REQUIREMENTS.md`; module numbers to `.planning/intel/SYNTHESIS.md`.

All code: Node.js 24, ES modules (`.mjs`), no npm dependencies, UTF-8 for every file written. Windows first (paths with spaces, CRLF, case-insensitive paths, `.cmd` shims); POSIX paths present.

## 2. Output and exit conventions (P8)

- One line per item on stdout. An item failure is one line `failed <what>: <err>` and makes the command exit 2 ("done with problems").
- Exit codes: 0 done; 1 usage error, config error or file error (nothing or nothing more done); 2 done with differences, conflicts, failed items or problems. `ph gsd` verbs add 66 (nothing in scope) and 69 (could not look / not ported) (GSDC-02); `ph` returns them unchanged.
- `ph` prints `usage error: <first line, <=300 chars>` for a `UsageError` and `failed: <first line>` for any other thrown error, both exit 1.
- Error text in a line is `errText(e)`: first line of the message, at most 300 characters.
- Non-blocking commands end with the `next:` wait hint (PHCL-07) rendered with `phCommand()` (section 5).
- `kit.mjs` (M1/M2): usage line on stderr + exit 1 for bad arguments; `failed: <msg>` for expected failures, `error: <msg>` for unexpected ones (INST-01, MACH-01).

Rules:
- No consumer embeds a default value or opens `harness.defaults.json` / `harness.config.json` itself (CONF-12). `.claude/harness.config.json` and `.planning/config.json` are never read (CONF-07, CONF-13).
- Overlay errors: not an object -> `invalid harness config overlay: expected an object`; unparsable -> `invalid harness config overlay: invalid JSON (<parser message>)`.
- Overlay keys starting with `_` are ignored at the top level only.
- A key another module needs is added to the schema by code-foundation first (file a request); never add keys from another module's code.

Wait policy (G144, `wait_timeout_s` and `agent_stop_s`): a workflow `agent()` with no `timeoutS` waits for its turn in slices of `wait_timeout_s`. While the watchdog is armed (`watchdog_enabled` true and `agent_stop_s` above 0), the wait goes on past `wait_timeout_s` until the turn ends or the watchdog stops the agent after `agent_stop_s` of model time (tool time is not counted, FLOW-29); a nudge that settles a slice as running does not end it. Unarmed (watchdog off, or `agent_stop_s` 0), `wait_timeout_s` caps the turn as before. An explicit `timeoutS` on the call bounds the whole call at that value. The waits of `cmd-start.mjs`, `cmd-agents.mjs` and `compact.mjs` keep `wait_timeout_s` as their cap.

Live retier (F45B, `workflow/retier.mjs`): while a workflow run owns a live agent (a call's agent while it runs, or an idle session agent it keeps), the overlay file `.agents/harness.config.json` is checked every 5 s by its mtime and size and read again only when it changed. A tier that resolves to another model of the same provider switches each live agent of it: `Session.setModel` (with readback), then `Session.setThinking` when the thinking level changed. Each switch logs `retier <label> <agent8>: <old> -> <new>` and is listed in the call's journal entry as `retiers`; the entry's `model` is the model the agent ends on, while the call's cost stays priced with the model it started on. A tier on another provider logs `retier <label>: <tier> moved to provider <p>; the running agent keeps <old>, the next call uses the new tier` and changes nothing. A failed switch is logged and never fails the call. The check runs only while the run owns a live agent and stops with the run. `ph model` applies the same rule by hand (runtime `cmd-agents.mjs`).

Thinking levels (`THINKING_LEVELS`): `off, low, medium, high, xhigh, max`.

## 7. Paseo client (M4): `ship/.agents/harness/paseo-client/index.mjs`

## 8. `ph` entry and command registry: `ship/.agents/harness/ph.mjs`

`node .agents/harness/ph.mjs <command> [args]`. `ph.mjs` owns parsing of the command name, `help`, `config`, error printing and exit codes; every other command lives in a command module owned by its coder.

Command modules (fixed list in `ph.mjs`, imported in this order; a module file that does not exist is skipped, any other import error fails `ph`):

| module | owner | commands (examples) |
| --- | --- | --- |

Each module exports `commands`, an array of command definitions:

```js
export const commands = [{
  name: "spawn",                      // first argv token; unique across all modules (duplicate -> ph fails)
  summary: "start named agents and return at once",   // one line in `ph help`
  usage: "ph spawn --name N (--prompt T | --prompt-file F) [--count K] ...",  // shown by `ph help <command>`
  options: { name: "string", count: "string", prompt: "string", "prompt-file": "string", "read-only": "bool" },
                                      // parsed by ph with parseArgs (PHCL-02); null = the handler gets raw argv (e.g. `gsd`),
                                      // which answers -h and --help itself; for a parsed command ph prints `usage` (G153)
  config: "required",                 // "required": invalid config -> `failed: invalid harness config ...` exit 1 (CONF-08)
                                      // "lenient": ctx.cfg = defaults and ctx.configError = the error (doctor only)
                                      // "none": no config load
  hidden: false,                      // true: not listed by help (internal commands such as the compact watcher)
  run: async (ctx) => 0,              // returns the exit code (undefined = 0); throw UsageError for usage errors
}];
```

Handler context `ctx`:

| field | meaning |
| --- | --- |
| `name` | the command name. |
| `argv` | raw tokens after the command name. |
| `opts`, `args` | parsed options and positional tokens (when `options` is not null). |
| `env` | the environment to use (never read `process.env` in a handler; tests pass their own). |
| `root` | `configRoot(env)`. |
| `cfg`, `configError` | effective config (`null` for `config: "none"`); `configError` only for `"lenient"`. |
| `out(line)`, `err(line)` | write one line (newline added) to stdout / stderr. |
| `write(text)` | raw stdout write (pass-through output). |
| `clock` | the clock (section 5). |
| `paseo()` | `Promise<Session>`: connects once on first call with `{env, root, cfg, clock}`; ph closes it in `finally`. |
| `ph` | `phCommand()` (for `next:` hints and teammate notes). |

Exit mapping in `main`: handler return value as is (0, 1, 2, 66, 69); `UsageError` -> `usage error: <msg>` exit 1; other error -> `failed: <msg>` exit 1.

Built-ins in `ph.mjs`: `help` / `--help` / `-h` / no command (usage + public command list, exit 0), unknown command (same text, exit 1), `<command> -h` / `--help` for a parsed command (its `usage` and summary, exit 0, the command does not run; G153), `config` (CONF-10: effective config as 2-space JSON with `_provenance`, exit 0; invalid config -> `failed: ...` exit 1).

`main(argv, {env = process.env, cwd = process.cwd(), out, err, write, clock, daemon} = {})` is exported for in-process tests (`daemon` is passed to `connect`; `ctx.root` = `configRoot(env, cwd)`). Error lines (`usage error:`, `failed:`) go to stderr; everything else to stdout. Run as a script, `ph.mjs` sets `process.exitCode = await main(process.argv.slice(2))`.

## 11. Review integration contracts (2026-10-20)

### Creation, deadlines and worktrees

- A post-creation usage-tracking error carries `{agentId, archived, archiveError}` and `cause` (the tracking error). `archived` is a confirmation boolean, not the truthiness of the error. The message says `(archived)` only after confirmation; otherwise it names the possible live agent and cleanup failure. Creation callers preserve that agent's worktree and capacity accounting until cleanup is confirmed.
- `waitTurn.deadline` is absolute milliseconds on `session.clock`. Waits and late-usage settling are capped to it; backoff and permission handling check expiry before sending anything else, and late waits/replies cannot succeed. `UsageTracker.settleTurn(agentId, turnsBefore, lastUsage, deadline = Infinity)` preserves exactly-once usage accounting within that allowance. Workflow `timeoutS` spans all turns/retries and the setup awaits: agent creation, the fetch or resume of an adopted agent, and the worktree git calls (each gets what is left of the budget; `runGit` takes `timeoutMs`). At the deadline the call ends null with `no reply within <timeoutS> s` without waiting for the RPC, which may stay pending in the client until the connection ends. A create that answers later archives the agent it started and the worktree is kept. Queue time in admission is not counted.
- Workflow `agent()` additionally accepts `detail`, `timeoutS`, and `worktreeSeed`. `detail` returns `{result, reason, agentId, worktree, durationS, model, effort}`, where `model` and `effort` are the resolved ones (`null` when the call did not resolve); `worktree` is the path even on cached non-session calls. An object script result is written to `result.json` with a `roles` list added (the run's effective roles). The `runId` script global is the original run of the resume chain.
- `worktreeSeed: {head, files: [{path, sha256} | {path, deleted: true}]}` is a runtime-owned accepted-dependency input for worktree isolation and is included in the cache key. The runtime validates HEAD, source identities, contained paths and absence of links before copying. It records the seed in the new worktree's git directory (`harness-seed.json`) before dispatch. Failures discard only that newly created tree. Session continuations reuse their tree, not reseed it.
- GSD batch executors obtain seeds only from earlier accepted transfer records. Transfer compares the worker against both HEAD and the recorded seed: unchanged dependencies are excluded, but modifying a seed or restoring it to HEAD is still a worker change subject to owns/deletion checks. Owned pre-execution dirty files remain refused; immutable content-addressed planning/skill/config snapshots supply uncommitted planning inputs. A change outside owns is dropped instead of refused when it matches `adapter.ownership.regenerated` or is a tracked file that differs from its base commit only in line endings (kit-feedback 26); the drop is logged and listed in the transfer record's `dropped`, and the main tree keeps its own version.
- Worktree removal (kit feedback 75). `discardWorktree(wt)` returns `{ok, reason?}` and `removeWorktree(top, wt, {force})` `{ok, removed, line}`; both first unlink every symlink / junction found in the tree (`worktree-links.mjs`, never following one; the recorded setup links are only a subset) and refuse, keeping tree, branch and lease, when a link stays, a folder cannot be listed or the tree root is itself a link. A transfer record file entry is `{path, sha256, wt_sha256}` (`wt_sha256` is the worktree content when it was copied; `adopt` may rewrite `sha256` only) and a `dropped` entry carries `wt_sha256` too; `ph worktrees` classifies a dirty tree with no commit ahead of HEAD whose every changed path is carried by a finished transfer record naming that worktree (or is an untouched seed file) as `transferred`, removable by `--prune` (git `--force`). The flow verb `gsd-flow discard-worktree` (stdin `{plan, worktree, reason: landed|halted}`) is how gsd-execute removes a tree: `landed` only when the tree is merged and clean or `transferred`, `halted` (a cleared halt is dispatched again; `halt-answers.json` entries carry `haltRunId` and `haltWorktree`) unless the run that owns it still runs; `leftover-worktrees` returns `{total, removable, names}` of harness worktrees of finished runs.

### Adapter and evidence

- `adapter/contract.mjs`: async `gateObligation(cfg, {codeRoot, phaseDir, kind, command, target})` returns `{outcome: ready|unavailable|not_configured, kind, argument, targets, argv, timeoutS, exitCodeSufficient, evidenceParser, reason}`. Parser failure supplies no executable argv. An empty target set for a kind that is not `exit_code_sufficient` is `unavailable` with reason `no concrete targets selected`. The default parser uses the trimmed argument; `{argument}` and `{targets}` are substituted before spawning.
- `adapter/evidence.mjs`: async `requiredSteps(cfg, {codeRoot, phaseDir, plans})` supplies the independent expected step set; `gateStepName` and `obligationStepName` share names between writer and reader; `executionProblem({targets, executed, exitCodeSufficient})` enforces nonzero execution/target coverage. A passed step must have exitCode 0 and an existing log; executed is `{count: number|null, targets: []}`.
- `flow-gate.mjs` `evidenceCheck` is async. Evidence captures inputs before the commands and rejects mutation during them. `inputs.scopes` records patterns for rescanning additions/deletions; `inputs.config` hashes only `adapter.commands` and `adapter.verify_vocabulary` from loadConfig (kit-feedback 58), so other adapter keys and gsd or harness settings do not make a gate's evidence stale. Missing-file identities and HEAD are checked. Null build/test produce `not_configured` steps, never green evidence.
- Hook requests/responses are closed shapes, nested records included. Exactly one nonblank stdout JSON line is accepted. Resolve must answer every requested target exactly once; shared may return only requested paths; attribute answers every failure once with a requested plan id or null. Unknown request fields throw; invalid responses become unresolvable.
- `adapter/mutex.mjs`: `tryLock(name, {tmp}) -> token|null`, `unlock(name, token, {tmp})`. A rename publishes `{pid, token}` ownership; stale recovery is serialized by a per-lock reap claim and release checks ownership. `acquireMutex(name, {log, clock, tmp})` waits and returns the release; `withMutex` reports waiting once. `runtime/cap-lock.mjs` `takeCapLock(root, caller, clock)` is the caller-wide agent cap lock (`_workspace/locks`, one per caller) that spawn, fanout, collect and each workflow call take around their count and create of agents.

### Adapter generation identity self-check

- Parser targets are canonical execution identities. Resolve validates those exact IDs, one result each; it cannot expand or rename them. File/suite aliases either expand in parse before runner argv substitution, or remain selectors only when completed runner records prove the selector's membership and completion. Request echoing, nonzero counts alone and discovery-only mappings are not execution proof. Skipped cases do not count.
- `adapter/check.mjs` exports `checkObligation(cfg, {codeRoot, kind, command, outputDir?, execute: true})`. Explicit opt-in runs the existing parse/resolve/runner/evidence protocol under the adapter mutex and uses unchanged `executionProblem`; no new config keys or hook fields. Returns a retained transcript `{v, kind, command, outcome, reason, directory, obligation?, resolve?, runner?, evidence?}`. Non-ok resolution stops before running; empty targets for non-exit-code-sufficient kinds, failed runners, failed evidence and incomplete coverage are rejected.
- Standalone CLI: `node .agents/harness/adapter/check.mjs --kind <kind> --command "<obligation>" --run [--output <dir>]`, from the project root (or `PASEO_HARNESS_ROOT`). Exit 0 passed, 2 rejected, 1 usage/config/error. Each call creates a fresh directory with `check.json` and runner logs under `_workspace/adapter-check/` by default. It executes project code only with `--run`; lint remains structural. This is not full gate evidence or a security boundary against a dishonest project hook.
- Generation readiness requires independent expected-ID/count assertions across every supported selector form (single, multi-test file, suite alias), plus rejection of zero execution, missing coverage, failed runner and unknown selector. Preserve real positive logs and labeled isolated negative controls; unavailable checks mean not ready. The kit overlay specifies this self-check without changing protected Harness/GSD method text.

### GSD diagnostics and durable flow records

- `gsd/upstream.mjs`: async `checkTarget(target) -> {problems, warnings, references, verbs, verbose}` is read-only and independent of project configuration. Doctor uses the selected root even when its overlay is invalid. Kit GSD namespaces remain inventoried; arbitrary project role files alongside them are allowed.
- `gsd/draft.mjs` `validateDraft` is shared by pre-approval checks and `roadmap install-draft` inside the single-writer lock. It requires nonempty categorized v1 coverage, exactly one matching phase per expected ID, no extra IDs, valid roadmap grammar and 2–5 criteria per phase before shared files change.
- `execute-progress.json` distinguishes coding SUMMARYs, commits and STATE tracking. A resumed partial transaction reruns required gates/reviews. Required code commits and record writes must succeed before tracking; wave/override writes must succeed before proceeding.
- Pending cross-plan requests persist until fix replies explicitly acknowledge them in `resolvedRequests`. Fatal failures stop the fix round at once; a fixer's owner decision stops it only after every fixer's owned changes are transferred and the gate has rerun, and only while that fixer's plan still fails (kit-feedback 51). A gate failure goes to the plans owning the file it is reported at (`path:line`); files a run merely names are not its failures when a position is given. Missing review judgments, unknown severities and quick verification without a fresh passing artifact fail closed.
- Execute, debug and quick acquire the root writer lock `debug` (the file keeps its name) for their whole run; execute also holds `phase-<NN>` for its whole run. Plan holds only `phase-<NN>` for its whole run (kit-feedback 2), so planning phase N+1 runs while phase N executes; a second plan of the same phase, or an execute of it, is refused with the holder's kind and run id. Acquire/reap/release use an exclusive transition claim, live host PID and owner token (not run-id equality). Interrupted transition claims fail closed and may require manual recovery.
- `ph gsd commit` takes `_workspace/locks/git-writer.lock` and waits for it (the STATE.md lock rule), so a plan's docs commit and an execute's code commit never collide on the git index. STATE.md and ROADMAP writes already take `STATE.md.lock` inside `writeShared`.
- Map-codebase acquires its own `codebase-map` lease for the whole run (not the debug one, so plan and execute keep pipelining); a second map on the same root is refused. The stamp refuses when HEAD moved since the mappers were dispatched (a commit landed during the map).
- Map-codebase checks the written docs before anything is stamped: the doc check rejects a Known Bug in CONCERNS.md that is neither `Status: verified` with its `Evidence:` nor `Status: suspected` (the message names the `## Checked, Not Bugs` section after Known Bugs, where a refuted claim goes); then the secrets scan; then the Review stage, one `map_reviewer` per focus area (read only) fact-checks its docs against the code, and an incremental map (`paths`) only the claims about those paths. Its findings go back to that focus's mapper once; a fix reply names every doc with a finding and nothing outside the focus. The docs are checked and the group gets a resolution check of its findings (its prompt carries a digest of the docs); findings that still stand stop the run `needs-owner` at stage Review, with nothing stamped or committed. A claim the resolution check raises anew goes to `review.findings` and does not stop the stamp. The mapped result carries `review: {checked, fixed, findings}`.
- Verify acquires a per-phase lock `verify-<NN>` from its attempt record through readback and routing, not the root writer lock; a second verify of the same phase returns `refused` while the first runs.
- Per-criterion verify (`gsd.verify_mode: per-criterion`): `ph gsd verification parts <phase>` checks and `verification merge <phase>` merges the parts named on stdin (`{attemptKey, parts: [{id: SC-<k>|phase, path, text}]}`). A part is valid when it holds the report's frontmatter rules, `criterion` equal to its id, `attempt_key` equal to this verify attempt's key, a path under `<phaseDir>/verify/` and a `covered_digest` that still matches its covered files; merge writes nothing unless every part is valid (exit 1 with each part's `problems`). The merged report carries `verify_mode`, `attempt_key`, `criteria` (id, text, status, part), `phase_checks` and a digest recomputed over the parts' covered files, and reads back through `verification status`. The script keeps a part already valid for its attempt (a `--resume` redispatches only the verifiers that did not finish), gives a part a verifier left invalid one rewrite naming its problems, stops the queue on a fatal reply, and returns `mode`, `criteria` (`id, text, status, reused`) and `dispatched`; a new run is a new attempt and verifies every criterion again.
- Research acquires a per-phase lock `research-<NN>` from its status check through readback, not the root writer lock; a second research of the same phase returns `refused` while the first runs. `revisions record` reads, merges and writes `revisions.json` under `revisions.json.lock` (the STATE.md lock rules), so concurrent records keep each other's keys. `revisions record` without `--settings` keeps the settings digest the workflow checks with (kit feedback 73): for `freeze`, `plan:<id>` and `checked` it reuses the `settings` part of the key's previous record, else of the newest record of its family (any `plan:*`), and says so in `settings {digest, source}`; with none to reuse it warns that the workflow's check will count the record changed. `--settings` still wins; `check` and `hash` are unchanged.
- Hand edits (kit feedback 68, same setting): `ph gsd hand-edit scan <phase>` lists the plans, planning artifacts (outline, manifest, wiring, skeleton lanes, research report) and transferred owned files that changed outside the flow since their last revisions record or transfer, and keeps them in `<phaseDir>/hand-edits.json`; a `revisions record` made by hand (outside a workflow run, whose shell calls carry `PASEO_HARNESS_WORKFLOW_RUN`) keeps the edit it overwrites. gsd-plan and gsd-execute run the scan after their lease and put `handEdits {pending, candidates, ask}` in the result and the log; they never stop for it. Answer each with `ph gsd hand-edit record <phase> <HE-n|plan:<id>|file> --category contract-drift|wrong-api|owns-reach|test-fixture|other --note "<one line>"` (an edit nobody scanned is logged the same way); `ph gsd hand-edit list <phase>` shows the log, and `ph review-stats` counts the logged hand fixes per category and phase and prints a category (not `other`) logged twice as a kit defect candidate. Owner inputs (CONTEXT, requirements, roadmap, role text) are not hand edits. A file the flow rewrote and did not record (a killed run) is listed too: answer `other`.
